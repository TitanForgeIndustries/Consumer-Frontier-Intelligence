# Security Policy

## Scope

This repository may eventually contain experimental machine learning systems, training tools, evaluation code, and supporting services.

Security reports should focus on vulnerabilities in the project itself, including code, dependencies, configuration, and project-maintained services.

## Reporting a vulnerability

Please do not disclose a suspected security vulnerability publicly in a GitHub issue before it has been reviewed.

Use GitHub's private vulnerability reporting feature when available. If it is not enabled, contact the repository maintainer through a private channel associated with the project.

Include a clear description, reproduction steps, affected component or version, potential impact, and any suggested mitigation.

## Sensitive information

Do not include API keys, credentials, private datasets, personal information, or other secrets in issues or pull requests.

## Research-specific note

Experimental model behavior that is merely surprising or undesirable is not necessarily a security vulnerability. When in doubt, describe it privately first so it can be triaged appropriately.
