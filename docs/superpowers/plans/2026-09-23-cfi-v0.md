# CFI v0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Train, save, load, and generate from an original CFI causal model with a physically selected hierarchical expert residual and a dense control.

**Architecture:** One small PyTorch package owns model and byte data; two thin scripts own experiment execution and independent checkpoint inference. Both modes share the causal core and training windows. All expert weights are resident in v0, while only a selected expert executes per token.

**Tech Stack:** Python 3.12, PyTorch 2.14 available in the repository's E: virtual environment, pytest, RTX 3070 8 GB.

**Spec:** `docs/CFI-V0-DESIGN.md`

## Global Constraints

- No Qwen weights or Transformers dependency in CFI v0 training or inference.
- Existing EXP-0001–0009R records remain unchanged; EXP-0010 gets its own artifact and document.
- Dataset, checkpoints, caches, results, and logs stay on `E:`; no generated artifacts enter Git.
- Report measured runtime and VRAM separately from theoretical active parameter count.

## Review Focus

1. A later token must not change earlier-token logits: test future perturbation with a causal mask.
2. Empty/too-small input must fail before creating a misleading checkpoint: test byte split bounds.
3. Inactive experts must not run: instrument calls and compare with routed IDs.
4. The router must receive gradients despite top-1 dispatch: assert nonzero finite gradients on a training loss.
5. Reloaded checkpoints must reproduce logits and generate with no Qwen import: round-trip test and standalone command.
