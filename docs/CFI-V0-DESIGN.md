# CFI v0: Shared Causal Core with Hierarchical Sparse Residual

Status: first reversible architecture candidate, 2026-09-23. The bounded [EXP-0010 smoke](experiments/EXP-0010-cfi-v0-smoke.md) completed with route collapse, poor text, and no sparse advantage. This is a **new independently trained model**, not a Qwen modification. It is not a claim of architectural novelty relative to all sparse MoE work, nor a frontier-level model.

## Objective and constraints

Produce a from-scratch locally trainable checkpoint that generates bytes without any Qwen model, tokenizer, or weights at inference. The first experiment tests only whether additional *total* expert capacity can be made conditional on a bounded *active* expert path. It does not test memory paging, knowledge lookup, adaptive reasoning, shared KV, or practical large-scale quality. Work on `E:` for corpora and artifacts. A single 8 GB GPU must support the bounded smoke configuration.

## Network

Input/output vocabulary: 256 UTF-8 byte values, no pretrained tokenizer. Learned token and position embeddings; a stack of pre-norm causal multi-head self-attention plus a shared dense FFN; final norm and tied output projection. Context window is finite and position embeddings restart on a cropped window during generation. Training uses next-byte cross entropy.

After the shared core, normalize and route each causal token state through two learned linear projections: choose one of `groups` and then one of `experts_per_group` within that group (top-1 at each stage). A selected FFN processes only the tokens assigned to it; unselected expert modules are not invoked. A differentiable selected-route probability scales the residual, and an auxiliary soft-probability/hard-load balancing penalty counteracts collapse. Router and experts stay resident on the same device. This is genuine conditional computation but **not** GPU-memory offloading. Statistics expose selected IDs and held-out route load/locality; parameter accounting distinguishes total resident versus estimated active per token, never substituting estimates for measured time/VRAM.

The dense control has exactly the same shared core and one always-executed FFN in place of the sparse router and experts. Its FFN width matches one active expert; it therefore roughly matches expert FLOPs, not total parameters. The paired runs use identical training windows and optimization budget. A future parameter-matched dense control and repeated seeds are required for any capability-efficiency claim.

## Data, artifacts, and CLI

Input: an explicitly supplied UTF-8 file; no automatic private-data discovery. Hash its exact bytes, split it contiguously into train and validation byte ranges with at least `context+1` bytes each. Prefix prompting uses byte IDs and replaces invalid UTF-8 sequences on display. A reproducible `--seed` samples the same train/validation windows for both models. A checkpoint records model configuration, mode, weights, data hash, seed, step, and vocabulary contract. Checkpoints, summaries, and full generated bytes/text are written to a new output directory on `E:`; an existing output directory is refused rather than silently overwritten. A standalone inference command loads only a CFI checkpoint and the local PyTorch runtime.

The first EXP-0010 smoke protocol is predeclared before running: an openly sourced small text corpus, deterministic 90/10 contiguous split, seed 42, sparse/dense paired runs, 32 steps, 8 windows of 128 input bytes per step, width 256, 4 shared blocks, 4 attention heads, 512 shared FFN width, 4 groups × 2 experts, each 512 wide, and a 256-byte context. AdamW at 3e-4, 4 fixed validation batches, 16 generated bytes for timing after 4 warmup bytes, two repeats, and a 64-byte generation example. The small compute/data budget measures plumbing and reproducibility, not generalization. The first checkpoint is expected to be much smaller than the eventual 100M–500M candidate; scaling is conditional on correctness and measured limits.

## Verification and stop rules

- Unit tests establish causality, exact sparse dispatch, gradient through router/selected experts, serialization and Qwen-independent generation, split validation, and the paired-batch contract.
- Validation records held-out NLL, total/active parameters, expert loads and transition locality, peak allocated GPU memory, fixed-token elapsed time, and examples. Fixed-token generation recomputes the finite window in both modes; timing does not include an optimized KV cache.
- If training throws or produces non-finite loss, write a separate implementation-failure artifact and stop; a CUDA device assert requires a fresh process. Do not invent or fill missing results.
- Completion of a smoke run establishes runnable infrastructure, not sparse superiority. Promote only after stronger data, multiple seeds, more training, parameter-matched dense controls, and physical profiling.
