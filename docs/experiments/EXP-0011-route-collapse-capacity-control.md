# EXP-0011: Route-collapse and useful-capacity control

Predeclared 2026-09-23, **before EXP-0011 training or held-out evaluation**; completed 2026-09-23. An eight-step synthetic-input CUDA timing calibration bounded the run; it was not trained on the corpus and is not a scientific result.

## Question and relevance

Can the independently trained CFI v0 model use more than one expert while retaining held-out quality at bounded active compute? EXP-0010 demonstrated checkpoint-only inference but collapsed to one route and lost quality and speed versus its dense control. If additional total capacity cannot be used selectively at competitive quality and measured latency on consumer hardware, do not promote paging or scale this candidate. This small byte-model experiment is **not** an assessment of frontier capability or general language competence.

## Fixed comparison

- Reuse exactly the EXP-0010 pinned tiny Shakespeare bytes (SHA-256 `86c4e6aa9db7c042ec79f339dcb96d42b0075e16b8fc2e86bf0ca57e2dc565ed`), contiguous 90%/10% split. No new corpus, tokenizer, Qwen initialization, teacher, or fine-tuning.
- Three independent initialization/data-window seeds **41, 42, 43**. Four conditions per seed, each initialized from scratch: (1) sparse baseline with existing auxiliary balance coefficient **0.01**; (2) sparse intervention with that coefficient changed only to **1.0**; (3) dense same-active-width control with FFN width **512**; (4) dense approximately parameter-matched control with FFN width **4096**. No other architectural or optimizer change. The latter costs more active compute and is a capacity, not compute-matched, control. The intervention is one fixed strong coefficient, not a search.
- Width 256; four causal blocks, four heads, shared FFN width 512, 4 groups × 2 experts of width 512, context 256. Byte vocabulary 256, tied output projection. AdamW LR 0.0003, weight decay 0.01; exactly **512** steps, batch 8, 128-byte input windows, fixed sampled-window stream per seed across all four conditions. No scheduler, early stopping, checkpoint selection, or validation-based tuning. Record full training trajectory and per-64-step sparse route loads.
- Held-out evaluation: 16 batches of 8 windows of 128 bytes (16,384 positions), validation-window stream seeded seed+1, identical within each quartet. Report per-seed held-out NLL, route histogram, effective expert count (exp of Shannon entropy), max-route share, and adjacent same-route rate. Record last and mean train NLL, exact train/validation window hashes, exact generation bytes and replacement-decoded text from `The ` plus 64 greedy bytes.
- Time after training: 16 generated warmup bytes, then 32 generated bytes for each of 3 repeats, same process/device and prompt. Both models recompute full cropped attention context; all expert weights stay on GPU. Report raw seconds, throughput, peak `torch.cuda.max_memory_allocated` bytes, total/resident and estimated active parameters. Short timings are exploratory, not KV-cache or paging benchmarks.
- All data/checkpoints/results remained under the original external data root; each condition has a unique new output directory, a fresh Python process, exact corpus/checkpoint hashes, software/GPU metadata, and separate implementation-failure JSON on failure. Never overwrite a prior run. A CUDA assert requires a fresh Python process. No partial run is silently treated as scientific completion.

## Decision gates and limitations

First verify the same-active-width dense median held-out NLL is <5.0 nats/byte (versus uniform ln(256) about 5.545); otherwise the training budget did not give this toy baseline a useful learning signal and the route comparison is inconclusive. The *route-use* gate is at least four experts with at least 1% of validation positions each and no single expert above 75%, in **all three** intervention seeds. The *quality* gate is intervention minus same-active-width dense held-out NLL at most 0.1 nats/byte in median and at most 0.2 in each seed. Report baseline-sparse and parameter-matched-dense comparisons independently; neither may be omitted because unfavorable. A separate *runtime* gate requires intervention median throughput at least same-active-width dense and measured allocated CUDA memory at most same-active-width dense; do not conflate this with parameter arithmetic. Route use alone does not meet quality or runtime gates.

These exploratory thresholds classify this fixed protocol; they are not statistically powered evidence of broad architectural superiority. On one tiny corpus, three seeds and a tiny model cannot establish useful general-language quality, scaling, expert semantics, hardware memory savings, or frontier capability. Preserve failures, raw artifacts and negative results. Decide subsequent work only after closing this experiment.

## Gate outcome and interpretation

- **Learning signal: pass.** Same-active dense median held-out NLL 2.760885 is below the predeclared 5.0 threshold. This supports interpreting the bounded routing comparison, not broad language competence.
- **Route use: pass.** All three strong-balance seeds use all eight experts at ≥1% with maximum shares below 75%. Raising the *existing* auxiliary coefficient from 0.01 to 1.0 prevents the observed collapse under this specific setup; it does not prove semantic specialization.
- **Quality tolerance: pass against same-active-width dense only.** Median paired difference is +0.013220 nats/byte and every seed is within +0.2. This is a tolerance gate, **not a sparse quality win**. The parameter-matched dense control is substantially better (median NLL 2.659234 versus 2.778289), so extra total sparse parameters have not yielded a useful-capacity benefit.
- **Runtime/memory: fail.** Median throughput is **161.22 vs 244.86 bytes/s** for balanced sparse versus same-active dense, about **0.66×**; every seed is slower. Peak allocated CUDA bytes are **52,344,832 vs 37,594,624**, about **1.39×**. All sparse weights remain resident; reduced arithmetic per token is not a measured consumer-hardware efficiency gain. Short runs fluctuate; no optimized KV cache or paging was tested.

**Decision:** close EXP-0011 as a reproducible router-collapse intervention with *no demonstrated capacity-efficiency advantage*. Do not promote the current v0 sparse architecture to the 100M–500M candidate, memory paging, or frontier-capability claims on this evidence. The consumer-local frontier goal remains unchanged, but the architecture must earn both useful capacity and actual resource benefit before scale-up. No subsequent experiment was started.
